# TrackBus v0.2 detection pipeline

This document defines the supported production path behind
`python -m trackbus.main`. Its central invariant is:

> Every decoded source frame produces exactly one update of exactly one
> ByteTrack instance, after all enabled views have been translated, excluded,
> and fused.

## Stage 1: decode one source frame

OpenCV decodes the original frame and retains its width, height, frame number,
and source FPS. All camera geometry is normalized against this frame. The
annotated output uses the same source dimensions; inference configuration cannot
crop the output or redefine the counting coordinate system.

## Stage 2: resolve enabled inference views

Each named view has normalized `[left, top, right, bottom]` bounds:

```yaml
camera:
  detection_roi: null
  inference_views:
    - name: full
      bounds: [0.00, 0.00, 1.00, 1.00]
      enabled: true
    - name: left_doorway
      bounds: [0.00, 0.15, 0.62, 1.00]
      enabled: false
    - name: right_doorway
      bounds: [0.38, 0.15, 1.00, 1.00]
      enabled: false
```

The default is one `full` view. Enabled views are cropped independently from the
same original frame. Names must be unique, bounds must be normalized and
non-empty, and at least one view must be enabled.

The side-view coordinates above are test-video examples only. Recalibrate them
for each camera and retain enough context to observe both counting zones.

## Stage 3: predict people without tracking

`UltralyticsDetector` calls `YOLO.predict` once per enabled view with:

- class `0` (`person`) only;
- configured confidence and image size;
- selected CPU or CUDA device;
- optional FP16 only on CUDA;
- no persistent tracker state.

It emits one model-independent `Detection` per YOLO box. Each record contains
the view-local `xyxy` box, confidence, class ID, source-view name, and metadata.
An inference result with no boxes returns an empty list and remains a normal
frame condition.

Model input can be a standard Ultralytics weight name or a trusted local file.
Explicit remote URLs are rejected. The adapter does not select, fetch, or trust
arbitrary third-party model URLs.

## Stage 4: translate and clip

For a crop beginning at source pixel `(view_left, view_top)`, each view-local
box is translated as:

```text
source_left   = local_left   + view_left
source_top    = local_top    + view_top
source_right  = local_right  + view_left
source_bottom = local_bottom + view_top
```

The result is clipped to the valid source-frame boundary. Metadata records that
the coordinate space is now `source` and retains the normalized view bounds.
Every downstream stage consumes only these translated boxes.

## Stage 5: filter configured static exclusions

The bottom-center anchor of every translated raw detection is tested against
`camera.exclusion_polygons`. A hit marks the detection excluded. Excluded boxes:

- remain in `.raw_detections.csv` with `excluded: true` when export is enabled;
- remain visible in calibration or visual debug output;
- do not reach fusion;
- do not consume ByteTrack state;
- cannot reach the counter.

Exclusions are for known door or camera structure only. TrackBus never creates
them automatically from likely-static observations. Configuration loading warns
if an exclusion overlaps any counting zone or configured doorway lane.

## Stage 6: fuse duplicate detections

Included source-coordinate detections enter conservative class-aware,
cross-view greedy NMS:

```yaml
detection_fusion:
  method: nms
  iou_threshold: 0.50
  confidence_strategy: maximum
  prefer_full_frame: false
```

Within each class, candidates are processed by descending confidence. A
candidate from a different inference view with IoU greater than or equal to the
positive threshold relative to a selected winner can be suppressed as a
duplicate. Detections from the same prediction call are never suppressed a
second time, and one fused group claims at most one detection from each view.
The winner keeps its box, the group keeps its maximum confidence, and it records:

- every contributing source view;
- selected fusion method and IoU threshold;
- confidence strategy;
- number of source and suppressed detections;
- contributing view bounds;
- suppressed boxes.

`prefer_full_frame: true` changes coordinate-winner priority to favor a
full-frame box. It does not average coordinates or replace the group's maximum
confidence. The current implementation intentionally supports only `method:
nms` and `confidence_strategy: maximum`.

NMS is not instance segmentation. Two nearby people whose overlap stays below
the threshold remain separate. If a large candidate ambiguously spans two
smaller candidates which do not overlap one another enough to be duplicates,
TrackBus retains the smaller hypotheses and records the discarded spanning box
in fusion metadata. It still cannot create a missing second detection.

## Stage 7: update one explicit ByteTrack instance

`ByteTrackAdapter` turns the fused set into an `N x 6` array:

```text
[left, top, right, bottom, confidence, class_id]
```

The adapter calls one Ultralytics `BYTETracker.update` for the original source
frame. It also calls the tracker with an empty `0 x 6` input when there are no
fused detections, which lets lost-track age and buffer behavior advance
correctly. It returns `TrackedDetection` records with temporary ID, tracker box,
confidence, class ID, source views, and fusion metadata.

This internal adapter is tested with Ultralytics `8.4.95` and all version-
sensitive imports, `Boxes` conversion, result-column assumptions, and error
messages are isolated in `trackbus/tracker.py`. Project dependencies pin that
version. An incompatible API raises `TrackerAdapterError`; production does not
silently fall back to the old combined `YOLO.track` pipeline.

Tracker behavior is configured through the referenced ByteTrack YAML. These
values can also be overridden under `tracking`:

```yaml
tracking:
  tracker: configs/bytetrack_trackbus.yaml
  track_high_thresh: null
  track_low_thresh: null
  new_track_thresh: null
  track_buffer: null
  match_thresh: null
  fuse_score: null
  minimum_zone_frames: 3
  stale_track_timeout: 90
```

Null values leave the tracker YAML unchanged. The effective values and installed
Ultralytics version are included in the run summary.

## Stage 8: classify and count conservatively

The bottom-center anchor of each tracked source-coordinate box is classified as
`OUTSIDE`, `INSIDE`, or neither. Optional lanes are diagnostic and can use the
box center or bottom-center, but they do not change the counting anchor.

The counter's first stable zone for a new ID establishes origin only. It never
counts `UNKNOWN -> INSIDE` or `UNKNOWN -> OUTSIDE`. A complete transition must
retain one ID and reach the opposite zone for `minimum_zone_frames` consecutive
frames. Returning to origin cancels the pending transition. Missing tracks do not
produce synthetic zone samples or invented events.

## Stage 9: diagnostics, exports, and annotation

Every frame updates existing doorway diagnostics after tracking. Those signals
include lane gaps, overlap, possible restarts, border contact, wide or multi-lane
boxes, and likely-static behavior. They are evidence for run comparison only;
they do not remove detections or emit events.

Enable optional frame-level exports with:

```yaml
diagnostics:
  export_detection_csv: true

outputs:
  raw_detections_csv: null
  fused_detections_csv: null
  tracks_csv: null
```

Null paths derive names beside the output video:

- `<stem>.raw_detections.csv` contains frame, timestamp seconds, source view,
  source box, confidence, class, and exclusion status;
- `<stem>.fused_detections.csv` contains frame, fused box, confidence, class,
  contributing views, and JSON fusion metadata;
- `<stem>.tracks.csv` contains frame, ID, box, confidence, class, anchor, zone,
  lane, counter state, and contributing views.

No files are opened when the flag is false.

For visual inspection, `camera.debug_calibration_overlay` draws views, lanes,
exclusion polygons, and excluded boxes. `diagnostics.debug_visualization` adds
raw and fused boxes, confidence, view provenance, trajectories, restart warnings,
and raw/fused frame totals. Zones, tracked boxes, IDs, state, and occupancy remain
available in ordinary output.

## Legacy configuration migration

Old full-frame configurations that omit both `camera.inference_views` and
`camera.detection_roi` continue to use one full-frame view.

An old non-null `camera.detection_roi` is accepted as one
`legacy_detection_roi` view and emits a deprecation warning. If that sole crop
covers less than half of `OUTSIDE` or `INSIDE`, another warning explains that it
may remove complete crossing history. Migrate it explicitly:

```yaml
# old
camera:
  detection_roi: [0.03, 0.30, 0.97, 1.00]

# explicit v0.2 equivalent; review coverage before using it
camera:
  detection_roi: null
  inference_views:
    - name: legacy_doorway
      bounds: [0.03, 0.30, 0.97, 1.00]
      enabled: true
```

Do not use both keys; TrackBus fails with a precise migration error. A sole crop
is not automatically made safe by renaming it. Prefer a full-frame view, or add
overlapping views while keeping tracking and counting in source coordinates.

## Verification invariants

Model-independent tests enforce these properties:

- view crop and coordinate translation are deterministic and clipped;
- exclusions occur before NMS and tracking;
- duplicate views merge while nearby distinct passengers remain;
- empty detection frames still update ByteTrack exactly once;
- every source frame produces one tracker update;
- view provenance survives fusion and tracking conversion;
- stable synthetic tracks reach the unchanged counting state machine;
- unsafe sole crops and exclusion-path overlap produce warnings;
- diagnostic exporters remain closed unless explicitly enabled.
